# Pang Kum — ชุดแจกจ่ายและอัปเดต

## โครงสร้าง
| ที่ | คืออะไร |
|---|---|
| `src/` | ไฟล์ที่ติดตั้งลงโปรเจกต์ Apps Script: `Code.gs` `ClientCode.gs` `Index.html` `Menu.gs` `Updater.gs` `Backup.gs` (ชื่อไฟล์ต้องสะกด **ตัวพิมพ์เล็ก-ใหญ่ตรงเป๊ะ** — `Clientcode` กับ `ClientCode` คือคนละไฟล์ และจะขึ้น error `Identifier 'CLIENT_B64' has already been declared`) |
| `client/client.js` | โค้ดหน้าเว็บ **ที่อ่านรู้เรื่อง** — แก้ที่นี่ แล้วรัน `node tools/build-client.js` ให้สร้าง `src/ClientCode.gs` (Base64) ให้ |
| `tools/` | `release.sh` (ออกเวอร์ชัน) `make-version.js` `build-client.js` · `add-customer.sh` `check.sh` `update.sh` (ผู้ดูแลอัปเดตให้ลูกค้าผ่าน clasp) · `appsscript.json.example` |
| `releases/manifest.txt` | แฮชของไฟล์ทุกเวอร์ชันที่เคยปล่อย (ใช้แยก "เวอร์ชันเก่า" ออกจาก "ลูกค้าแก้เอง") |
| `customers.csv` | รายชื่อลูกค้า (คัดลอกจาก `customers.csv.example`) |
| `version.json` | ไฟล์ที่ระบบของลูกค้าอ่านเพื่อเช็คเวอร์ชัน และใช้เป็นรายการไฟล์ + แฮชสำหรับปุ่ม "อัปเดตระบบ" (สร้างโดย `tools/release.sh` อย่าแก้มือ) |

## เลือกวิธีอัปเดตให้ลูกค้าแต่ละกลุ่ม
| กลุ่ม | วิธีอัปเดต | ลูกค้าต้องตั้งค่า |
|---|---|---|
| ร้านที่คุณดูแลให้ | `tools/update.sh` (clasp) | แชร์สิทธิ์ Editor ให้บัญชีผู้ดูแล — **ไม่ต้องผูกโปรเจกต์ Cloud** (clasp ใช้ OAuth ของตัวเอง) |
| ร้านที่อยากกดอัปเดตเองในแอป | ปุ่ม "อัปเดตระบบ" (ผ่าน GitHub) | **ต้องผูกสคริปต์กับโปรเจกต์ Google Cloud มาตรฐานของตัวเอง** + เปิด Apps Script API (ดูหัวข้อด้านล่าง) · ผูกด้วยโค้ดไม่ได้ ต้องทำในหน้า Project Settings |
| ร้านติดตั้งเอง (แจกฟรี) | แบนเนอร์แจ้งเวอร์ชันใหม่ แล้ววางไฟล์เอง | ไม่ต้องตั้งอะไร (วางให้ครบทุกไฟล์ใน `src/`) |

ไฟล์ `Backup.gs` เป็นไฟล์ตั้งค่าของลูกค้า (อีเมลสำรอง จำนวนไฟล์ที่เก็บ) จึง **ลงให้ครั้งแรกเท่านั้น ไม่ถูกทับตอนอัปเดต**

## ติดตั้งเครื่องมือ (ครั้งเดียว)
1. `npm i -g @google/clasp` แล้ว `clasp login` ด้วยบัญชีผู้ดูแลระบบ
2. เปิด Apps Script API ที่ https://script.google.com/home/usersettings
3. เครื่อง macOS/Linux ที่มี `bash`, `perl`, `shasum` หรือ `sha256sum` (มีอยู่แล้วโดยปกติ)

## เพิ่มลูกค้าใหม่
1. ลูกค้าแชร์โปรเจกต์ Apps Script (หรือชีต) ให้บัญชีผู้ดูแลเป็น **Editor**
2. คัดลอก Script ID (Project Settings) แล้วรัน
   `tools/add-customer.sh shop1 <scriptId> [deploymentId] [ลิงก์ webapp]`
3. ถ้าไม่ได้ใส่ Deployment ID สคริปต์จะแสดงรายการให้ เลือกตัวที่เป็น Web app (ไม่ใช่ `@HEAD`) แล้วใส่ใน `customers.csv`

## ออกเวอร์ชันใหม่
1. แก้โค้ด (`src/Code.gs` และ/หรือ `client/client.js`)
2. เพิ่มเลข `APP_VERSION` และ `APP_DATE` ใน `src/Code.gs`
3. `node tools/build-client.js` (ถ้าแก้หน้าเว็บ)
4. `tools/update.sh all --dry-run` ดูก่อนว่าจะเปลี่ยนอะไร
5. `tools/update.sh all` — แต่ละร้านจะ ดึงของเขามาเช็ค → ใส่ไฟล์ใหม่ → push → deploy ลิงก์เดิม (ลิงก์ที่ลูกค้าใช้ไม่เปลี่ยน)
6. (ทางลัด แทนข้อ 3 และ 6) `tools/release.sh "ข้อความบอกว่ามีอะไรใหม่"` — สร้าง `ClientCode.gs` + `version.json` (พร้อมแฮชของทุกไฟล์) + ลงทะเบียน `manifest.txt` ในคำสั่งเดียว แล้ว `git add -A && git commit && git push`

## ลูกค้ากดอัปเดตเองจากในแอป (ผ่าน GitHub)
ลูกค้า (เจ้าของร้าน) จะเห็นแบนเนอร์แดง **"มีเวอร์ชันใหม่"** ด้านบนสุดของหน้าพนักงาน (ตรวจตอนเข้าสู่ระบบและทุกชั่วโมง) → กด **ไปอัปเดตที่ ตั้งค่า** → กด **⬆️ อัปเดตระบบตอนนี้** ระบบจะ:
1. อ่าน `version.json` → ดึงทุกไฟล์จาก GitHub → **ตรวจแฮช** (ไม่ตรง/ไม่ครบ = ไม่แตะโปรเจกต์เลย)
2. สร้าง **เวอร์ชันสำรอง** ของโค้ดเดิมใน Apps Script (ย้อนกลับได้ที่ Deploy > Manage deployments)
3. เขียนโค้ดใหม่ (ไม่ทับ `appsscript.json` ไม่ทับ `Backup.gs` ที่ลูกค้าตั้งค่าไว้ ไม่แตะข้อมูลในชีต) → สร้างเวอร์ชัน → ชี้ลิงก์ Web app เดิมไปเวอร์ชันใหม่ → หน้ารีโหลดเอง
สำรองอีกทาง: เมนูในชีต **Other Tools > ⬆️ อัปเดตระบบจาก GitHub**

**ตั้งค่าครั้งเดียวต่อโปรเจกต์ลูกค้า** (ต้องทำมือ เพราะให้สคริปต์ตั้งสิทธิ์ให้ตัวเองไม่ได้) — ทำเสร็จแล้วกดเมนู **Other Tools > 🩺 ตรวจความพร้อมระบบอัปเดต** (หรือปุ่ม 🩺 ในหน้าตั้งค่า) จะบอกเป็นข้อๆ ว่าขาดอะไร พร้อมลิงก์แก้
1. ใน Apps Script: Project Settings > ติ๊ก *Show "appsscript.json" manifest file* → เพิ่ม `oauthScopes` ตาม `tools/appsscript.json.example` (ต้องมี `script.projects` `script.deployments` `script.external_request`) — ถ้าไฟล์ของลูกค้าเดิมไม่มี `oauthScopes` ให้คัดลอกรายการทั้งหมดนั้นไปวาง
2. เจ้าของเปิดสวิตช์ **Google Apps Script API** ที่ https://script.google.com/home/usersettings (ด้วยบัญชีเจ้าของสคริปต์)
3. **ผูกโปรเจกต์ Google Cloud มาตรฐาน** (จำเป็น เพราะการเรียก Apps Script API จากในสคริปต์ผ่านโปรเจกต์ Default ที่ Google สร้างให้ มักขึ้น `Apps Script API has not been used in project ... or it is disabled` และคุณเปิดเองไม่ได้ เพราะโปรเจกต์ Default ไม่โผล่ในคอนโซล):
   1. สร้างโปรเจกต์ที่ https://console.cloud.google.com/projectcreate
   2. เปิด **Apps Script API** ที่ https://console.cloud.google.com/apis/library/script.googleapis.com (กด Enable)
   3. ตั้ง **OAuth consent screen** (External, ใส่ชื่อแอพ/อีเมล, เพิ่มตัวเองเป็น Test user หรือกด Publish app)
   4. คัดลอก **Project number** จาก Dashboard → Apps Script > Project Settings > **Change project** → วางเลข → Set project (**กลับไปใช้ Default ไม่ได้อีก** และสิทธิ์เดิมจะถูกยกเลิก ต้องอนุญาตใหม่)
4. เปิดชีต → เมนู **Other Tools > 🔑 อนุญาตสิทธิ์** → กดอนุญาต (แล้ว Deploy > New version เองครั้งนี้ครั้งเดียว)
5. ตั้ง `ตั้งค่า > เวอร์ชันระบบ > ลิงก์ไฟล์เวอร์ชัน` เป็น `https://raw.githubusercontent.com/<ผู้ใช้>/<repo>/main/version.json`

ข้อควรรู้
- ไฟล์ทั้งหมดต้องอยู่ใน repo เดียวกับ `version.json` (เส้นทางใน `version.json` นับจากโฟลเดอร์เดียวกับไฟล์นั้น) — repo ต้องเป็น **public** เพราะระบบดึงด้วยลิงก์ raw ไม่มีรหัส · ถ้าไม่อยากเปิดโค้ด ให้ใช้ `update.sh` (clasp) แทน
- **ใครเขียนลง repo ได้ = สั่งรันโค้ดในบัญชี Google ของลูกค้าทุกรายได้** เปิด 2FA ให้บัญชี GitHub และอย่าแชร์สิทธิ์ push
- raw.githubusercontent.com แคชประมาณ 5 นาที หลัง push ถ้ากดอัปเดตแล้วขึ้นว่าแฮชไม่ตรง ให้รอแล้วลองใหม่
- อัปเดตจะไม่ทำให้ออเดอร์หาย (ข้อมูลอยู่ในชีต) แต่หน้าที่เปิดค้างอยู่ต้องรีเฟรช ควรกดตอนไม่มีลูกค้าสั่ง
- **โควตาเวอร์ชันของ Apps Script = 200 ต่อโปรเจกต์** ปุ่มอัปเดตสร้าง 1 เวอร์ชัน (ข้ามเวอร์ชันสำรองเมื่อโค้ดที่แก้อยู่ตรงกับเวอร์ชันที่ Deploy อยู่ ไม่งั้นสร้าง 2) ระบบเตือนเมื่อใช้ถึง 180 และหยุดก่อนแตะโค้ดถ้าไม่พอ · ลบเวอร์ชันเก่าที่ตัวแก้ไข Apps Script > Project history (ลบได้เฉพาะเวอร์ชันที่ไม่ได้ใช้ใน Deployment)
- ตรวจเวอร์ชันใหม่ตอนเข้าสู่ระบบและทุกชั่วโมง (ฝั่งเซิร์ฟเวอร์แคช 6 ชม. จึงไม่ยิง GitHub ถี่) + มีปุ่มตรวจเอง ไม่ต้องตั้ง trigger เพิ่ม
- ถ้าเวอร์ชันใหม่ใช้บริการ Google เพิ่ม (ต้องใช้สิทธิ์ใหม่) ใส่ใน `SCOPES` ของ `tools/make-version.js` แล้วลูกค้าต้องกด **อนุญาตสิทธิ์** ในชีตอีกครั้งหลังอัปเดต
- ใช้กับแอพอื่น: ดูหัวข้อ "เอาระบบอัปเดตไปใช้กับแอพอื่น" ด้านล่าง

## ตรวจว่าลูกค้าแก้โค้ดเองไหม
`tools/check.sh all` แสดงเวอร์ชันของแต่ละร้านและสถานะไฟล์
- `✓ ตรงต้นฉบับล่าสุด`
- `เก่ากว่าต้นฉบับ: …` = เป็นเวอร์ชันเก่าที่เราเคยปล่อย อัปเดตได้ปลอดภัย
- `⚠ แก้เอง: …` = เนื้อไฟล์ไม่ตรงกับเวอร์ชันไหนที่เคยปล่อย

`update.sh` จะ **ข้ามร้านที่ถูกแก้เอง** และบอกให้ไปดูไฟล์ที่ `customers/<ร้าน>/` ถ้าจะทับจริงใช้ `--force` (ระบบสำรองไฟล์ของเขาไว้ที่ `backups/` ก่อนทุกครั้ง)

ถ้ามีลิงก์ Web app ใน `customers.csv` สคริปต์จะถาม `?page=ver` ให้ด้วยว่าเว็บจริงตอบเวอร์ชันอะไร

## ลูกค้ากลุ่มติดตั้งเอง (แจกฟรี)
ใช้ไฟล์ใน `src/` แจกทั้ง 5 ไฟล์ ลูกค้าวางทับแล้ว Deploy → New version เอง โดยตั้งค่า `ตั้งค่า > เวอร์ชันระบบ` ให้ชี้ `version.json` ของคุณ จะรู้เองเมื่อมีเวอร์ชันใหม่ ลูกค้ากลุ่มนี้ตรวจว่าแก้โค้ดเองไหมไม่ได้ (คุณไม่มีสิทธิ์เข้าโปรเจกต์)

## ข้อควรระวัง
- `clasp push` **แทนที่ทั้งโปรเจกต์ด้วยไฟล์ที่ส่งไป** สคริปต์จึง pull ก่อนทุกครั้ง เพื่อให้ไฟล์อื่นของลูกค้า (เช่น `appsscript.json`) ไม่หาย และไม่แตะ `appsscript.json` ของลูกค้า
- ครั้งแรกที่ติดตั้ง/อัปเดตเวอร์ชันที่เพิ่มการเรียกอินเทอร์เน็ต (`Backup.gs`, ตัวเช็คเวอร์ชัน) ให้ลูกค้าเปิดชีตแล้วกดเมนู `Other Tools > 🔑 อนุญาตสิทธิ์` หนึ่งครั้ง ไม่งั้น Apps Script ขอสิทธิ์ใหม่แล้วหน้าเว็บอาจขึ้นว่าต้องอนุญาต
- เมนูในชีตอยู่ที่ `Menu.gs` ที่เดียว (`onOpen` มีที่เดียว) ห้ามเพิ่ม `onOpen` ใน `Code.gs` อีก
- สคริปต์ทดสอบกับ `clasp` จำลองเท่านั้น ยังไม่ได้ลองกับบัญชี Google จริง ให้ลองกับโปรเจกต์ทดสอบของคุณเองก่อน (`update.sh <ร้าน> --dry-run`)

## เอาระบบอัปเดตไปใช้กับแอพอื่น
ระบบอัปเดตแยกเป็นชิ้นเดียวคือ `src/Updater.gs` (หัวไฟล์ลิสต์ฟังก์ชัน/ค่าที่ต้องมีในแอพ) ทำตามนี้
1. **คัดลอกไฟล์ในแอพใหม่**: `src/Updater.gs` และเมนูจาก `src/Menu.gs` (`mUpdate` `mReady` `mAuth` + ตัวช่วย `authUrl_` `runAuthed_` — ถ้าแอพมี `onOpen` อยู่แล้วให้เพิ่มรายการเมนูเข้าไป อย่าให้มี `onOpen` สองที่)
2. **ในแอพต้องมี**: ค่าคงที่ `APP_VERSION` / `APP_DATE`, ฟังก์ชัน `authOwner_(pin)`, `set_()` (คืน object ที่มีช่อง `update_url`), `rows_` `sh_` `withLock_` `bust_` และ `audit_` (ลบบรรทัดที่เรียก `audit_` ได้ถ้าไม่มี)
3. **หน้าเว็บ**: เรียกฟังก์ชัน `checkUpdate(pin, force)` `applyUpdate(pin)` `checkReady(pin)` `saveUpdateUrl(pin, url)` และ **ถ้าโค้ดหน้าเว็บอยู่ในวงเล็บ `(function(){...})()` ต้องส่งฟังก์ชันที่ใช้ใน `onclick` ออกไปที่ `window` ด้วย** (`Object.assign(window,{chkVer,chkReady,doUpdate,goUpdate,...})`) ไม่งั้นกดปุ่มแล้วเงียบ (เคยเป็นบั๊กใน v39)
4. **repo**: ใช้ repo เดียวหลายแอพได้โดยแยกโฟลเดอร์ เช่น `apps/pangkum/version.json` และ `apps/wallet/version.json` (ระบบคำนวณที่อยู่ไฟล์จากลิงก์ `version.json`) — คัดลอก `tools/make-version.js` + `release.sh` + `common.sh` ไปไว้ใน repo/โฟลเดอร์ของแอพนั้น แก้ `FILES` (และ `SCOPES` ถ้าแอพต้องการสิทธิ์เพิ่ม) ให้ตรงไฟล์ของแอพ
5. **appsscript.json**: ทำไฟล์ตัวอย่างต่อแอพ ใส่สิทธิ์ของแอพนั้นครบตั้งแต่แรก + `script.projects` `script.deployments` `script.external_request` เพื่อให้ลูกค้าไม่ต้องไล่เพิ่มเอง
6. ให้ลูกค้ารันเมนู **🩺 ตรวจความพร้อมระบบอัปเดต** ครั้งเดียว แล้วแก้ตามรายการ
